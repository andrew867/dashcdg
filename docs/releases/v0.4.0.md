# Release v0.4.0 — Desktop resilience, ESP32 karaoke polish, repair-NACK hygiene

Date: 2026-05-10

This release tightens **desktop TX/RX** behavior under loss and long sessions,
extends **Opus** decoder setup for safer RX lifecycle use, improves **CDG batch
jitter** coverage, and lands **ESP32 badge** UI/receiver work plus supporting
docs and tooling.

## Highlights

- **RX:** Per-group **CDG repair-NACK** cooldown and masking so duplicate/masked
  holes do not spiral into log or wire storms; **CONNECTING / reconnecting**
  overlay logic is clearer when Opus frames arrive before CDG anchors apply.
- **TX:** **Playlist** scanning handles empty or stuck libraries with **rescan**
  and logging; **repair-NACK** handling caps burst work on the stats/repair path
  (full rebroadcast thresholds, repairs-per-event limits, cooldowns) so PTP-thread
  overload is less likely under flood conditions.
- **Core:** **CDG batch jitter** gains stronger invariants and **unit tests**
  around timeline alignment edge cases.
- **Opus:** Decoder exposes **explicit init** paths suited to RX **open/close**
  and **codec switch** scenarios; roundtrip test updated accordingly.
- **ESP32 badge:** LVGL/home/settings flows, RX/touch/Wi-Fi integration, lab/YMM
  hooks, and **Kconfig** defaults aligned with ongoing karaoke reliability work.
- **Documentation:** RCAs for **TX crash / player stoppage**, **long-track NACK
  storms**, and **ESP32 A/V** issues; specs and test plans for **v4 repair-NACK
  throttle** and **ESP32 karaoke hardening**; **badge build/flash** runbook;
  helper **scripts** for IDF builds and log summaries.

## Desktop runtime and transport

- v4 remains the default wire path; playlist-driven TX continues to interoperate
  with cold-join RX.
- TX repair response remains bounded; new limits prioritize keeping the control
  plane responsive when receivers ask for many repairs.

## ESP32 / embedded

- Firmware sources under `platform/espidf/projects/dashcdg_badge/` incorporate
  display and settings refinements and RX-side fixes aligned with the published
  specs and plans (full parity with desktop is still an ongoing goal).
