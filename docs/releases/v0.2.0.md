# Release v0.2.0 — Desktop + ESP32 handoff

Date: 2026-04-26

This release rolls up the recent stabilization pass across desktop TX/RX,
packaging/docs polish, and ESP32 implementation handoff material.

## Highlights

- Desktop TX now isolates the audio send path from non-audio control-plane work
  with a dedicated audio domain (`g_tx_ad`) and batched v4 RX-stats ingest.
- RX/display sync better follows heard audio on Windows by using effective host
  output latency (PortAudio/WASAPI path) instead of callback-span-only timing.
- Observability is deeper: periodic thread deadline-miss reporting, v4 RX-stats
  ingest drop visibility, and richer TX fault/status telemetry.
- Documentation sweep: refreshed root README, improved docs index and
  contributing guidance, plus architecture notes for TX audio isolation.

## Desktop runtime and transport

- v4 transport remains the default wire path, with v3 compatibility via `--v3`.
- TX wire sequence allocation is unified through `dashcdg_tx_next_wire_sequence()`.
- PTP thread no longer mutates main RX-stats state directly; v4 RX stats are
  ingested under a small mutexed queue and batch-applied on the main TX thread.
- Audio send and FEC release use the dedicated audio-domain lock path so
  hot-path send timing is less sensitive to non-audio work.
- Periodic status/fault logging now includes:
  - per-thread deadline-miss counters
  - v4 RX-stats ingest drop count
  - existing audio timing and queue pressure context

## Audio/video sync and latency handling

- RX/desktop audio timestamping now uses an effective latency model that takes
  the maximum of:
  - callback time-info span, and
  - `Pa_GetStreamInfo()->outputLatency` (important on WASAPI)
- Result: on-screen graphics/HUD timing better matches what listeners hear,
  especially on Windows hosts where negotiated output latency is higher.
- WinMM stream latency compensation was also tuned for better timestamp alignment.

## Resilience and nerdy codec/repair details

- v4 bounded FEC/repair flow remains in place for media robustness.
- CD+G PACK parity/Reed-Solomon observability work continues in-tree through:
  - parity inventory and analysis docs
  - TX-side PACK parity health telemetry instrumentation
- Codec support and switching documentation is consolidated for v4 IDs across
  desktop paths (Opus + narrowband family modules).

## Desktop build and packaging

- Windows outputs continue to include:
  - GL receiver/transmitter paths
  - GDI receiver/transmitter paths
  - headless TX
  - retro and legacy packaging variants in sneakernet bundles
- Build/version identity stays git-stamped in desktop startup logs for soak traceability.

## ESP32 / embedded status in this release

- ESP32 badge direction and implementation references are updated in docs:
  - desktop behavioral reference for v4 timing/session expectations
  - heap-backed jitter ring specs/test plans and implementation notes
  - codec and sync roadmaps for phased embedded adoption
- This release is not claiming full desktop feature parity on ESP32 yet; it
  provides a cleaner handoff and implementation contract for that path.
